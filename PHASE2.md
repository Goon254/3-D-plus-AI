## Track A — Four flagship showcase films + one vertical reel (top priority)

Goal: four **super-high-quality** shorts that make people say "an AI made this?", plus one 9:16 reel. These are the face of the project on the website and in the README.

Each film: 20–40 s, 1920×1080 (render at 960×540–1280×720 with Cycles, then 2× upscale with Real-ESRGAN per docs/research/05 **only if** the critic confirms it looks better than a native render; otherwise render native 1080p), voice + lip sync + music + SFX + captions, title card, end card "Made with Animatica". Different characters, settings, moods and camera language so the set shows range:

1. **Emotional** — "A lonely lighthouse keeper robot repairs a broken music box during a storm. When it finally plays, it says: 'There you are.'" (warm interior light vs. cold storm, rain, close-ups, slow push-ins)
2. **Comedy** — "A tiny fox chef tries to flip a giant pancake for the first time. It lands on his head. He says: 'Nailed it.'" (bright kitchen, snappy timing, squash & stretch, comic beat on the reaction)
3. **Wonder / adventure** — "A young astronaut cat discovers glowing jellyfish floating above an alien ocean at night. She whispers: 'They're beautiful.'" (bioluminescence, haze, wide establishing → close-up, drifting camera)
4. **Action / energy** — "A skateboarding robot races through a neon city at night, dodging traffic cones, and lands a huge jump. It shouts: 'Let's go!'" (fast cuts, motion blur, dynamic camera, music with drive)
5. **Vertical reel (9:16, 15 s)** — a punchy social-media cut built from shot material of the films above or a new micro-story; captions burned in large and centered-safe, loud hook in the first second.

Required engine upgrades to reach this bar (implement as needed, tested, in the existing architecture):
- Character variety: new character recipes (fox, cat astronaut, lighthouse robot, skater robot) through the rig interface in docs/AGENTS.md; real **walk/run/skate cycles** and expressive acting per story instead of one reused 4-beat arc.
- Environments: interior, kitchen, alien ocean, neon city recipes; textured materials (procedural + CC0 from docs/research/01), atmosphere/haze, rain/particles, emissive/bioluminescent materials, motion blur.
- Camera language per genre (comedy timing, action cutting, slow wonder drifts); `--aspect 9:16` support end to end (camera framing, captions, Editor).
- Audio: SFX layer (CC0 / jsfxr / synthesized), genre-specific music (MIDI-in-code; MuseScore render as optional upgrade per research 05), ducking, −14 LUFS.
- Editor via **MLT** (`melt`) per research 05: title/end cards, transitions where appropriate, and export `edit.mlt` + a Kdenlive-openable project for artist hand-off.

Deliverables: `examples/showcase/<slug>/` with `final.mp4` (≤ 25 MB each; compress with H.264 CRF tuned for quality), poster frame `poster.jpg`, 6-second looping `teaser.mp4` (muted, for the website hero), `contact_sheet.jpg`, production log. The hourly reviewer must score each film ≥ 9/10 on visuals, animation and audio from extracted frames before it is called done; re-render until it is.

A futuristic, beautifully animated marketing + docs site that **itself demonstrates** the tool: its hero animation, 3D visuals, icons and title art are generated by Animatica.

- Stack (per docs/research/04): static site, TypeScript + Vite (or Astro) + three.js; no server needed. Deploy with GitHub Actions to **GitHub Pages** (`.github/workflows/pages.yml`). Lives in `site/`. Lighthouse performance ≥ 90 on mobile; respects `prefers-reduced-motion`; accessible (contrast, alt text, keyboard nav).
- Design direction: dark, futuristic, cinematic. Glassy panels, subtle grain, depth, smooth scroll-driven reveals. Distinctive typography (open-license fonts only, e.g., from Google Fonts with OFL). Not a generic template look. Read the `frontend-design` guidance if available in your session.
- Pages/sections:
  1. **Hero**: full-bleed looping teaser rendered by Animatica (Track A `teaser.mp4`) or a real-time three.js scene built from an exported glTF of an Animatica character; headline + "Use it in Claude" and "View on GitHub" buttons.

## Track C — Hosted remote MCP connector ("use it in Claude")

This is how users "connect their Claude subscription": they add our server as a **custom connector** in Claude (Customize → Connectors → Add custom connector → paste URL). Claude, on the user's own plan, drives the tools; our server does the rendering.

**Policy constraint (do not violate):** Anthropic does not allow third-party products to offer claude.ai login or to use users' Claude subscription limits inside our own app. So: no "Sign in with Claude" button on our site and no use of subscription OAuth tokens. The connector route and bring-your-own API key are the compliant options.

- Upgrade `animatica-mcp` to **remote** MCP over Streamable HTTP (official Python `mcp` SDK, current spec, Tasks extension for long renders), alongside stdio.
- Tools exposed (coarse-grained, token-efficient): `start_film(prompt, style?, aspect?, quality?)`, `job_status(job_id)`, `get_result(job_id)` (returns links + poster + short summary), `revise(job_id, instruction)`, `list_showcase()`, `start_game(prompt)`, `render_preview(job_id, shot)`. Long jobs return immediately with a job id; results are links, not blobs.
- Auth: OAuth 2.1 for the connector (per MCP auth spec) with our own lightweight user accounts (email magic link or GitHub OAuth), or API-key header as a simpler first version. Per-user quotas and rate limits.
- Job system: queue (RQ or Celery + Redis per research 04), worker containers with Blender/Kokoro/Rhubarb/ffmpeg baked in (Dockerfile in `deploy/`), object storage for outputs (S3-compatible; avoid AGPL MinIO/Garage per research 04 — use a managed bucket or a permissively licensed option), signed expiring URLs.
- Deployment: `deploy/` with Dockerfiles, docker-compose for local, and a documented one-command deploy to a GPU-capable host (document Modal, RunPod, Fly.io or similar; do not hard-wire one vendor). CPU fallback works, slower.
- Safety: content policy filter on prompts, no voice cloning, per-user limits, logs without storing secrets.
- Test: an integration test that runs the remote server locally, calls the tools over HTTP, and gets a preview-quality film.
