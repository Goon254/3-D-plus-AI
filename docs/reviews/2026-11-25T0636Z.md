## Found: a real mastering bug behind a flaky test

The test's pink-noise bed was unseeded, so every run mastered a different mix. A 40-seed sweep of `master()` failed
2 (seed 6: **+1.3 dBTP, −15.5 LUFS** after four lower limits). ffmpeg's default AAC coder (`twoloop`) overshoots hard
clicks chaotically in the limit (−2 → −0.4 dBTP, −4 → +3.6, −10 → −3.1) while the limiter's own output was always
right, so "lower the limit by the excess" (#90) could diverge and always cost loudness. The real film's footsteps and
gush are this kind of signal, so the delivered film could have missed −1 dBTP without the loop noticing it was stuck.

## Built (DECISIONS #125)

`master()` keeps the default encode when it passes; if it doesn't and the encoder is native AAC, it re-encodes once
at the same limit with `-aac_coder fast` (ffmpeg's default in 4.0–4.3), then lowers the limit only if still needed,
and reports `aac_coder`. Sweep after: **60 / 60** seeds ≤ −1 dBTP at −14.0 / −14.1 LUFS. The test is seeded and runs
the failing beds (6, 9, 54, 59) plus 1. LESSONS row added. No design, scene or film render changed.
